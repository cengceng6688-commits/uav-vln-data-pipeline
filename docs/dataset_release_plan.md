# Dataset Release Plan

## Overview

This document proposes a staged release plan for the real-world goal-level navigation video dataset. The project is currently a pilot dataset construction pipeline for goal-level navigation videos with spoken instructions, aligned navigation clips, quality analysis, and structured metadata.

The dx, dy, dyaw action interface is retained for future extensions, but ground-truth action labels are not part of the current midterm deliverable. Reliable action labels would require additional sources such as visual odometry, SLAM, synchronized sensor logs, or UAV telemetry.

## Release Stages

### midterm_demo: Current Pilot Version

The midterm demo version is the current pilot dataset used for research presentation and internal review. Its purpose is to demonstrate that the pipeline can process raw videos into structured goal-level navigation samples without overclaiming dataset scale or action-label completeness.

Expected components:

- Raw videos used for the pilot run.
- Trimmed navigation clips.
- `dataset_index.jsonl` with one record per processed sample.
- Summary reports with sample counts, success rate, quality scores, timing statistics, and instruction type distribution.
- Case visualizations for a small number of representative samples.
- ASR evaluation subset based on manually annotated transcripts.
- Optional pseudo-action fields, if generated, clearly marked as non-ground-truth.

The midterm demo should not claim to provide ground-truth dx, dy, dyaw action labels.

### v0.1: 30-50 Samples

The v0.1 release target is approximately 30-50 valid samples. Its purpose is to provide a small but inspectable dataset for early feedback from senior students, advisors, and collaborators.

Expected components:

- Raw videos, stored separately from generated artifacts when possible.
- Navigation clips produced by the trimming pipeline.
- `dataset_index.jsonl` with documented schema.
- Summary reports for dataset quality and instruction analysis.
- Case visualizations for selected examples.
- ASR evaluation subset with manually annotated ground-truth transcripts.
- Optional future action labels only if their source and limitations are clearly documented.

At this stage, the emphasis should be on data validity, documentation clarity, and reproducible processing.

### v1.0: 500-2,000 Samples

The v1.0 release target is approximately 500-2,000 valid samples. Its purpose is to support more systematic research experiments and more reliable statistical analysis.

Expected components:

- Raw videos or access instructions for the raw video archive.
- Navigation clips organized by split or subset.
- `dataset_index.jsonl` files for the full dataset and each subset.
- Summary reports covering scale, success rate, failure reasons, timing distributions, instruction type distribution, and ASR quality.
- Case visualizations covering diverse instruction types, environments, and quality levels.
- ASR evaluation subset with a larger manually checked sample.
- Optional action-label extension if visual odometry, SLAM, sensor logs, or telemetry become available.

The v1.0 release should introduce explicit subset definitions, such as train, validation, and test splits, if downstream modeling experiments are planned.

### large-scale: Target 200K-Scale Samples

The long-term large-scale version target is 200K-scale samples. This is a future ambition rather than a current claim.

Expected components:

- Large raw video archive with consistent collection metadata.
- Navigation clips generated by a stable and versioned pipeline.
- Sharded `dataset_index.jsonl` files or equivalent scalable metadata format.
- Dataset statistics at global and subset levels.
- Representative case visualizations rather than exhaustive visualization for every sample.
- ASR evaluation subset with systematic manual sampling.
- Optional action labels derived from reliable sources such as visual odometry, SLAM, sensor logs, or UAV telemetry.

At this stage, release engineering becomes important. The dataset should include versioning, checksums, split definitions, schema documentation, data licenses, and reproducible processing scripts.

For future releases, the same structure can be nested under version names such as `v0.1/`, `v1.0/`, and `large_scale/`.

## Action Label Policy

The current project should distinguish clearly between three categories:

- Ground-truth action labels: not available in the current midterm version.
- Pseudo-actions: optional experimental labels, not real odometry.
- Future action labels: possible only with visual odometry, SLAM, sensor logs, or UAV telemetry.

This policy should be repeated in the README, dataset schema documentation, and presentation slides to avoid overstating the current dataset.
